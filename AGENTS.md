# tgbot_price_search

Telegram-бот (`autosnab_bot`). Python `>=3.14,<3.15`, пакетный менеджер — `uv` (запрещено вызывать голые бинари, только `uv run ...`).

`priceformation/` — git-сабмодуль со своим репозиторием и своим `AGENTS.md`. Здесь он исключён из всех проверок (ruff, black, mypy, vulture, bandit, pytest) и правится только в своём репозитории.

## Проверки после правок кода
Порядок и команды — из CI `.github/workflows/python-app.yml`; тот же набор в `.pre-commit-config.yaml`. Запускать из корня по всему репозиторию:

1. `uv run pytest` — порог покрытия 95% (`--cov-fail-under=95`), при недостижении тесты «падают».
2. `uv run black --check --diff .`
3. `uv run ruff check .`
4. `uv run flake8 .`
5. `uv run mypy .`
6. `uv run lint-imports` — контракты слоёв из `pyproject.toml [tool.importlinter]`.
7. `uv run vulture`
8. `uv run bandit -r autosnab_bot -c pyproject.toml`
9. `uv run pip-audit`

Правила запуска:
- Всегда по **всему репозиторию**, не сужать до изменённых файлов или затронутых тестов. Флаги не переопределять (`--select`, `--strict`, пути, `--min-confidence`) — конфиг берётся из `setup.cfg` / `pyproject.toml`.
- Задача не считается выполненной, пока все команды не завершились с exit 0. Пропускать можно только при чистом вопросе без правок или по явной просьбе пользователя.
- `lint-imports`: новый импорт против направления слоёв `handlers` → `services` → `config` убирать, а не глушить `ignore_imports` — развернуть зависимость (передать объект аргументом, вынести общее вниз).
- `vulture`: запускать без путей (`paths` из `[tool.vulture]`; `.` захватит `.venv` и `priceformation`). Код и тесты сканируются вместе. Мёртвый код удалять; неиспользуемый аргумент обработчика/хука — префикс `_`; остальные ложные срабатывания — whitelist-модуль в `[tool.vulture] paths`.
- `bandit`: сканируется только `autosnab_bot`; ложное срабатывание — `# nosec` с пояснением.
- `pip-audit`: при находках обновить версии в `[project] dependencies` / `[dependency-groups] dev` и `uv.lock`.

### Подавление линт/типов
`# noqa`, `# type: ignore`, `# nosec`, whitelist vulture — **только в крайнем случае**. Сначала исправить: переименовать, сузить тип, вынести функцию, убрать мёртвый код.

- **`autosnab_bot/`**: подавление без попытки поправить запрещено. Допустимо лишь на время рефакторинга по плану (задача ещё впереди) — тогда рядом обязателен `FIXME`: что не так, почему нельзя сейчас, **когда** починят (номер задачи / этап). Когда задача из `FIXME` делается — снять `noqa` вместе с комментарием, а не переносить дальше.

  ```python
  # ❌ заглушить и забыть
  class SearchReply:  # noqa: WPS214

  # ✅ на время плана
  class SearchReply:  # noqa: WPS214  FIXME: этап 2 — формат ответа раздувает класс; снять после выноса форматтера
  ```

- **Тесты** (`tests/`): тоже в крайнем случае (например, доступ к приватному API, который иначе не проверить). Не глушить «шум», который лечится именем теста, константой или хелпером.

### Быстрые команды (`justfile`)
Рецепты повторяют команды выше, ничего не переопределяя; `just --list` — список. Аргументы pytest передаются **без** `--` (иначе `--` уходит в pytest как путь).

- `just unit` — тесты без покрытия; `just unit tests/test_x.py -k case` — точечный запуск.
- `just test` — полный прогон с покрытием, как в CI.
- `just lint` (black, ruff, flake8), `just types` (mypy, lint-imports), `just audit` (vulture, bandit, pip-audit), `just check` — все проверки без тестов, `just ci` — проверки + `pytest`.
- `just format` — автоформат (`black`, `ruff check --fix`).
- `just run` — бот в текущем терминале (`uv run python -m autosnab_bot`).
- `just start` / `stop` / `restart` / `status` / `logs` — бот в фоне: PID в `bot.pid`, лог в `bot.log` (оба в `.gitignore`).
- `just service-install` — systemd-сервис пользователя (шаблон `deploy/autosnab-bot.service`): `Restart=always`, автозапуск при старте системы (нужен `sudo loginctl enable-linger $USER`); `service-status` / `service-restart` / `service-logs` / `service-uninstall`. Одновременно запускать только один экземпляр бота (`start` и сервис не совмещать).

## Коммиты
Не коммитить автоматически: `git commit` и `git push` — только после явного подтверждения пользователя. Закончив правку и проверки, показать итог и спросить, коммитить ли; разрешение на один коммит не распространяется на следующие.

## Секреты и логи
Токены и пароли из `.env` не попадают в код, тесты, логи и сообщения об ошибках. Библиотеки, которые логируют URL запросов, держать на уровне `WARNING` и выше (`httpx` — см. `main()`). Не печатать и не коммитить содержимое `.env*`, `bot.log`, файлов состояния.

## Тесты
- Параметры — `pyproject.toml [tool.pytest.ini_options]`: branch-покрытие, `--strict-config`, порог 95%. Тестовый код покрытием не измеряется.
- Тесты не ходят в сеть и не читают боевые `.env` и файлы состояния: внешние зависимости подменяются фейками (`tests/fakes.py`), общие фикстуры — `tests/conftest.py`, хелперы данных — `tests/price_helpers.py`. Тест, зависящий от локального `.env`, пройдёт у разработчика и упадёт в CI — значения конфигурации подменять через `monkeypatch`.
- Новое поведение — вместе с тестом; тест называется по поведению, а не по функции.

## Архитектура
- Слои сверху вниз: `autosnab_bot/handlers/` (Telegram: команды, колбэки, форматирование ответов) → `autosnab_bot/services/` (логика без знания о Telegram) → `autosnab_bot/config.py` (настройки из `.env`). Импорты только вниз; контракт проверяет `uv run lint-imports`. Сервисы не импортируют `telegram` и обработчики; бизнес-логику не писать в обработчиках.
- Точка входа и сборка приложения — `autosnab_bot/__main__.py` (регистрация обработчиков, проверка конфигурации при старте).
- Настройки читаются из окружения в одном месте (`config.py`); остальной код получает значения оттуда, а не обращается к `os.environ`.
- Стиль: black, line-length 120, кавычки одинарные (`skip-string-normalization`). Комментарии и docstring — на русском.

## Как искать причину, а не править следствие (обязательно)

Главное правило: **сначала локализуй корень проблемы, потом меняй код**. Запрещено «затыкать» симптом (подавить исключение, добавить `# noqa`/`# type: ignore`, расширить `try`, ослабить проверку, подогнать тест под текущее поведение), не поняв, почему он возник. Если причина не найдена — это не повод менять следствие; это повод сузить зону поиска.

Порядок действий при любом падении/расхождении:

1. **Прочитать сообщение целиком.** Не только последнюю строку: traceback, тип исключения, имя файла и строку, входные данные, если они есть. Ошибки несут контекст — использовать его.
2. **Определить слой по симптому.** `handlers` — разбор апдейта, ответ пользователю; `services` — поиск, прайсы, запуск внешних команд; `config` — окружение и пути. Проверить направление зависимостей (`uv run lint-imports`): если симптом «протёк» не в свой слой, причина, скорее всего, в нарушении контракта слоёв, а не в месте падения.
3. **Воспроизвести минимально.** `just unit tests/test_x.py -k <case>`; не запускать весь CI, пока не локализован кейс: полный прогон маскирует причину шумом.
4. **Сузить до входа.** Проверить, воспроизводится ли на минимальных данных из `tests/price_helpers.py` и на конкретном сообщении/файле. Отделить «данные» от «кода».
5. **Найти первый неверный шаг, а не последний.** Идти по цепочке от входа: апдейт Telegram → обработчик → сервис → внешний источник/файл → форматирование ответа. Ошибка должна быть воспроизведена на самом раннем шаге, где данные уже неверны; фикс — там, а не в конце цепочки.
6. **Проверить инварианты, а не подогнать результат.** Типы (mypy в `strict`), контракты функций, формат входных файлов. Нарушение инварианта — это и есть причина; менять надо инвариант или его проверку, а не вывод.
7. **Один фикс — одна причина.** Не смешивать в одном изменении рефакторинг, подавление линта и правку логики. Если правка тянет за собой ещё симптом — вернуться к шагу 2: вероятно, найден не корень.
8. **Закрепить тестом на причину.** Тест должен падать на исходном коде и проходить после фикса, проверяя именно корень, а не следствие (например, «бот что-то ответил»). Тест лежит рядом с причиной: тесты слоя, где она найдена.
9. **Подавление — только как явное исключение.** `# noqa`/`# type: ignore` допустимы лишь в крайнем случае, с указанием правила и FIXME-форматом (см. «Подавление линт/типов»); они не являются фиксом и не заменяют поиск причины.
10. **Зафиксировать вывод.** В сообщении/комментарии к правке указать: симптом, найденную причину, слой, почему фикс именно там, какой тест это закрепляет. Если причина не найдена — явно написать, что именно проверено и где остановился поиск, вместо «временного» подавления.

Красные флаги (почти всегда означают, что правят следствие):

- расширение `try/except` вокруг падения без изменения причины;
- `# noqa`/`# type: ignore`/`cast` вместо исправления типа или контракта;
- ослабление проверки в тесте/ассерте под текущий вывод;
- правка форматирования ответа, когда неверны данные на входе;
- обход слоёв (сервис импортирует обработчик или `telegram`, `config` — сервис) ради «быстрого» доступа;
- тест, который проходит только с локальным `.env` или сетью;
- «временный» хак без FIXME и без теста на причину.

Полезные команды при поиске: `just unit ...` (точечно), `just run` / `just logs` (воспроизведение в боте), `uv run lint-imports` (контракты слоёв), `uv run mypy .` (типы как индикатор неверного контракта, а не как то, что надо подавить).
